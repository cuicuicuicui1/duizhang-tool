# 往来单位对账函工具 · 使用说明

一个装在你自己电脑上的小工具，专门干三件事：

1. **批量生成对账函** —— 把往来单位的余额和明细自动填进正式函件，一次出几十份 PDF 和 Excel。
2. **回函核对** —— 对方回函回来，把差异**定位到具体哪几笔**，而不是只知道"差了 4 万块"。
3. **归档留痕** —— 每次生成的函、回函、差异报告都按单位和版本留档，只增不删，审计随时能查。

> 这个工具**不碰账务**：不记账、不生成凭证、不调账。它只是把"发函—收函—找差异"这条手工活变成自动的。

---

## 一、怎么启动

1. 双击项目目录里的 **`start.bat`**。
2. 会弹出一个黑色窗口（这是服务在运行，**不要关掉**），浏览器自动打开 http://localhost:3210。
3. 用完了，直接关掉那个黑窗口就是停止。

如果提示找不到 Node.js，就去 https://nodejs.org/ 装一个 22 版（一直点下一步即可），再双击 `start.bat`。

---

## 二、第一次使用：三步走

### 第 1 步：设一下我方公司信息（『模板设置』页）

填上公司名称、地址、电话、经办人。这些会印在对账函抬头上。

> 顺手在『设置』页选一下**余额口径**（见下文第四节）。拿不准就保持默认"自动"。

### 第 2 步：把明细账导进来（『数据导入』页）

从财务软件里导出往来单位的**明细账**（应收/应付账款），支持 `.xls` / `.xlsx` / `.csv`（GBK 编码的也能读）。

点"解析并预览"，工具会：

- 自动跳过前几行的公司名、报表标题、导出日期，找到真正的表头；
- 自动认列（借方/贷方、金额+方向、日期、摘要、科目……认不出来可以手动下拉指定）；
- 自动剔除"小计/合计"行；
- 自动识别"期初余额"行；
- 处理千分位、括号负数、全角数字、文本型数字、`--` 空单元格这些脏数据。

核对预览没问题就点"确认入库"。**入库前工具会自动备份数据**，同一份文件重复导不会重复入库。

### 第 3 步：出函（『批量生成』页）

选截止日 → 勾选单位（能看到各家余额）→ 一键生成。

同时产出：

- **PDF**：直接打印盖章寄出（A4 版式，含回函联和逐笔明细附页）；
- **Excel**：需要改字或补内容时用；
- **zip 打包**：一批单位一次性下载。

同一家单位同一期间重复生成，会生成"版本 2"，**旧版本永远保留**。

## 三、回函回来了怎么核对（『回函核对』页）

1. 上方选一份对账函。
2. 填对方回函上的**余额**（照抄即可），可选三种方式补充明细：
   - **只填余额**：最省事，工具只做余额比对，提示你索取明细；
   - **导入对方的明细文件**：工具自动认列，认不出来可以手工指定；同一家单位的格式认过一次就会**记住**，下次自动套用；
   - **粘贴**：直接从对方的 Excel 里复制几行粘进去，Tab/逗号/空格分隔都能认。
3. 点"开始勾对"。结果会分成六类列出来：

| 分类 | 颜色 | 含义 |
|---|---|---|
| 完全一致 | 绿 | 两边金额和日期都对得上 |
| 时间性差异（在途） | 黄 | 金额一样、日期差几天，典型在途 |
| 组合匹配 | 蓝 | 我方 5 笔 = 对方 1 笔（汇总付款、合并开票） |
| 我方有、对方无 | 红 | 对方漏记 |
| 对方有、我方无 | 红 | 我方漏记 |
| 可疑记录 | 黄 | 方向记反、疑似重复记账、金额相同但日期差太大 |

> **重要**：勾对结果一定是**草稿**。要你逐项看过、点"确认无误并归档"，状态才会变成"已确认"，差异报告才写进归档目录。

如果对方给的是他们自己账套导出的明细（借贷方向跟我们相反），勾选"对方明细方向翻转"即可；工具发现翻转后能对上时也会主动提示你。

## 四、口径到底是什么（『设置』页）

这是最容易出错的地方，所以工具把选择权留给你：

**"我方账面余额"从哪里算？**（六选一）

| 选项 | 什么时候用 |
|---|---|
| 用导出文件里的期初余额 | 明细账里带"期初余额/年初余额/上期结转"行或列 —— 最准 |
| 直接累计明细账的借贷 | 你导出的区间从建账/年初起是完整的 |
| 期初余额由我手工录入 | 手里有期初数，愿意在单位档案里填一次 |
| 以科目余额表为准 | 余额直接取科目余额表的期末余额列，明细账只用来勾对 |
| 分次导入累加 | 先导期初表、再导期间明细，数据一批批补齐 |
| 自动（推荐） | 先找期初，找不到就用累计法，并在函上提示"口径待确认" |

其它可选项：余额的正负号怎么表示、既是客户又是供应商时是否抵销（默认**分别列示不抵销**）、对账函是否附逐笔明细、大写金额元位为零的写法、**科目自然方向字典**（见下）、PDF 生成通道与并发数。

**列映射模板库（开源共享的适配层）**：不同财务软件的导出格式各有差异，自动识别覆盖不了的，在导入向导里调好列映射后点「把当前映射存为模板」——模板按**表头特征**匹配，下次导入同款软件的文件时自动提示一键套用。模板可导出成 JSON 文件分享给其他用户，也可从 JSON 导入别人的模板。**一种软件的导出格式，适配一次全网复用**——这是本项目应对"格式碎片化"的核心答案，欢迎为你在用的财务软件贡献模板。

**科目自然方向字典**只在一种情况下被用到：你导出的明细账**只有一列金额、且没有"方向"列**——这时工具必须靠科目名判断"这个正数是借方还是贷方"。默认清单覆盖常见的应收/应付/预收/预付类科目；你单位的科目若有特殊命名（比如"内部往来""往来款-XX公司"），在『设置』页把关键词加进对应清单即可。

**怎么核对**：导入预览页里，每一行都会列出工具**解析出来的借方/贷方金额**，拿你已知方向的几笔流水对一下就行——尤其是冲销、红字那几行。

**换了口径，余额就会变**。所以每个单位第一次出函后，建议跟账面核对一遍再发出去。

## 五、归档与备份

- **归档目录**：`data/archive/{单位}/{期间}/v{版本}/`，里面有对账函 PDF、Excel、回函原件、差异报告（JSON + HTML）。
- **自动备份**：每次导入确认、每次批次生成前，自动把数据文件备份到 `backups/` 下（只备份 JSON，体积很小）。
- **整包备份**：『历史归档』页点"整包备份（zip）"，把 `data/` 整个打包（含原件和归档），适合拷到移动硬盘或网盘。
- **恢复**：『历史归档』页可以从备份列表里一键恢复（**恢复前会自动把当前数据再备份一次**，不会把现在的数据弄丢）。
- 归档**只增不删**：重复生成走版本 +1，程序里没有删除文件的动作。

## 六、常见问题

**Q：生成的 PDF 打不开 / 说没有 PDF 引擎？**
A：工具用的是你电脑上已装的 Edge 或 Chrome 来打印，不额外下载任何东西。如果两个浏览器都没有，工具会自动改出"打印版 HTML"——用浏览器打开它，按 Ctrl+P 选"另存为 PDF"即可。也可以去『设置』页手动指定浏览器路径。

**Q：PDF 里的中文会不会乱码？**
A：不会，走的是系统浏览器打印，用的是系统字体（宋体/黑体）。

**Q：金额显示不对？**
A：先看『设置』页的余额口径，再看导入预览里有没有黄色的错误提示（比如单元格写的是"1.5万元"，工具**不会**自动换算，会明确报错让你先换算成元）。

**Q：能同时处理"既是客户又是供应商"的单位吗？**
A：可以。工具会把应收、应付余额**分别列示**在同一张函上，不会擅自抵销，并提示你人工确认是否净额结算。

**Q：一次能处理多少家？**
A：实测 50 家单位 × 每家 200 行明细，从算余额到出齐 PDF + Excel 约 45 秒。5 万行的单家明细也能处理。
（PDF 默认「复用单个浏览器实例」逐份打印，约 0.24 秒/份；若你的机器上 puppeteer-core 装不全，会自动回退到兼容模式——每次新开浏览器，约 1.1 秒/份，这时才用得上『设置』里的并发数，默认 4，调大反而互相争抢变慢。）

**Q：数据存在哪里？会不会传到网上？**
A：全部存在本机项目目录的 `data/` 下，**不联网、不上传、不需要登录**。

## 七、给懂技术的人

```
start.bat / server.js        入口（Express 本地服务，端口 3210，可用 DZ_PORT 改）
src/money.js                 金额红线：全程整数「分」，脏格式解析在这里
src/daxie.js                 人民币大写
src/dates.js                 日期归一（含 Excel 序列数）
src/columns.js               智能列识别（别名字典可配）
src/importer.js              导入解析、期初识别、小计剔除、指纹去重
src/units.js                 往来单位档案
src/ledger.js                余额计算（六种口径策略注册表）
src/templates.js             模板渲染
src/statement.js             批量生成、编号、版本、归档
src/exporter.js              ExcelJS 导出 + 浏览器打印 PDF + zip
src/matcher.js               回函四级勾对算法
src/replyAdapter.js          回函格式适配（自动识别/格式记忆/手工映射/粘贴四层降级）
src/archive.js               归档树、备份恢复、统计
src/routes.js                全部 API（统一 {ok, data, err}）
public/                      前端单页（原生 JS，无构建）
templates/                   对账函模板（HTML + {{占位符}}，可在界面里改）
tools/rdtest/                六层测试脚本
tools/fix-deps.js            依赖完整性自检（受限网络下 npm 漏文件时用它补）
```

跑测试：

```bash
node tools/rdtest/run_all.js          # 全部（约 4 分钟）
node tools/rdtest/run_all.js --quick  # 快速（跳过 50 家规模用例）
node tools/rdtest/run_all.js t4 t7    # 只跑指定套件
```

测试隔离：每个套件用独立临时数据目录（`DZ_DATA` / `DZ_BACKUP` 环境变量），不碰真实数据。

设计决策与对原计划的偏离，见 **`DESIGN_决策记录.md`**。
